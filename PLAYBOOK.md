# TF Lab Playbook — Terraform → Azure at ~NZ$0

**Goal:** prove a production-shaped Terraform pipeline (remote state, OIDC, managed identity) using only free tiers.
**Stack:** React on Static Web Apps (SWA) Free → .NET 10 Web API on App Service F1 → Azure SQL free offer.
**Expected run cost:** cents per month (state storage only). Budget alert at NZ$10 as a guardrail.
**Workstation:** GitHub Codespaces dev container — free monthly quota (120 core-hours ≈ 60 h on the 2-core machine, 15 GB storage).

> **Memory hook — deployment order: "Please Build Carefully: Infra, Database, API, Web, Smoke"**
> **P**rereqs → **B**ootstrap → **C**ommit → **I**nfra → **D**atabase → **A**PI → **W**eb → **S**moke
> Prereqs = open the **dev container**. Nothing is installed on your laptop.

---

## 1. Decisions (Winner / Runner-up / Avoid)

| Area | Winner | Runner-up | Avoid — why |
|---|---|---|---|
| Front end | SWA Free | Storage static website (cents) | App Service for static files — wastes the one F1 slot |
| API | App Service Linux F1 | Container Apps consumption (free grant, more moving parts) | Functions-as-API rewrite — changes the app to fit the host |
| Database | SQL free offer, `AutoPause` on exhaustion | SQL serverless (pay per use) | DTU Basic — ~NZ$8/month, always on |
| Pipeline auth | GitHub OIDC federated credential | Local `az login` only | Client secret in GitHub — long-lived, leakable |
| SQL auth | Managed identity, Entra-only | SQL login + Key Vault | Password in app settings/code |
| State | Blob, Entra auth, versioning, soft-delete, lock | Terraform Cloud free | Local state / shared access keys |

**Trade-offs in one line each**
- **Cost:** everything free-tier except state storage (cents). SQL `AutoPause` means *no overage bill*, ever.
- **Security:** zero stored secrets end to end. Accepted lab gap: SQL "Allow Azure services" (F1 has no VNet).
- **Ops complexity:** one bootstrap script, one pipeline, one teardown.
- **Maintainability:** plain azurerm + one AzAPI resource (free-offer flag azurerm lacks).
- **Scalability:** none, by design — F1 = 60 CPU-min/day. Swap SKUs to scale; code doesn't change.
- **Vendor risk:** free tiers can change terms — budget alert catches it.

## 2. Architecture and data flow

```
 Browser ──HTTPS──► SWA Free (eastasia edge)       static React files only
    │
    └──HTTPS/CORS──► App Service F1 (australiaeast)  .NET 10 API, system-assigned managed identity
                         │  Entra token (no password)
                         ▼
                     Azure SQL free offer (australiaeast)  Entra-only auth, TLS 1.2+

 GitHub Actions ──OIDC──► Entra app (federated, no secret)
    ├─ Contributor on rg-tflab-ause only
    ├─ Blob Data Contributor on tfstate container only
    └─ member of grp-tflab-sql-admins (SQL admin)
```

**Data assessment (lab = dummy data only)**

| Question | Answer |
|---|---|
| Originates | Seed row in `db/001-schema.sql` — synthetic, no real data |
| Processed | App Service, Australia East |
| Stored | Azure SQL Australia East; Terraform state in Australia East blob |
| Access | API MI = read-only (`db_datareader`); SQL admin = Entra group (you + pipeline) |
| Retention | State: 7-day soft delete + versions. SQL: default PITR backups (free) |
| Audit | Entra sign-in logs, Activity Log (free). SQL auditing off (costs storage) |

**Leakage risks flagged up front**
- Terraform state holds resource metadata — Entra-only access, no public blob, no keys.
- SWA metadata lives in East Asia (no SWA region in Australia). Static files only — no data.
- Never load real SkyCity data into this lab; it's a personal subscription outside corporate controls.

## 4. Runbook

### P — Prereqs (dev container — nothing installed on your laptop)

**Winner: GitHub Codespaces.** Runner-up: VS Code + Docker Desktop → "Dev Containers: Reopen in Container" (same file, runs locally). Avoid: hand-installing tools — versions drift and it pollutes your machine.

1. **Guard the free quota:** github.com → Settings → Billing → **Budgets** → Codespaces budget **$0** with "stop usage" on. Settings → Codespaces → **Default idle timeout 30 min**.
2. **Repo:** github.com → New repository → **Private**, name `tflab-azure`, tick **Add a README** (creates `main`).
3. **Open a codespace and load the files** (no local git needed):
   - Repo page → **Code** → **Codespaces** → **Create codespace on main**.
   - Drag the starter zip into the Explorer pane, then in the terminal:
     ```bash
     unzip -o DaveYang-TfAzLab-Starter-*.zip && cp -a tflab-azure/. . && rm -rf tflab-azure DaveYang-TfAzLab-Starter-*.zip
     git add -A && git commit -m "Lab scaffold"     # commit only — push happens at Step C, after bootstrap
     ```
   - Press **F1** → **Codespaces: Rebuild Container**. ~3–5 min; the log ends with tool versions + "Dev container ready".
   - (Already have git locally? Push the folder to the repo instead, then create the codespace — the container builds first time.)
4. **Sign in to Azure:** `az login --use-device-code` → open the link on any device, enter the code, pick the pay-as-you-go subscription (confirm: `az account show -o table`).
5. **Sign in to GitHub with your own account:**
   ```bash
   unset GITHUB_TOKEN
   gh auth login -s workflow      # GitHub.com → HTTPS → Login with a web browser
   gh auth setup-git              # git push now uses your login (needed to push workflow files)
   ```
   Why: the Codespaces built-in token can't set repo variables or push workflow files. Bootstrap checks and stops if this is missed.

> `unset` only lasts for that terminal. New terminal → run `unset GITHUB_TOKEN` again before bootstrap.

### B — Bootstrap (once, ~5 min)
```bash
bash bootstrap/00-bootstrap.sh
# optional: ALERT_EMAIL=you@example.com BUDGET_AMOUNT=5 bash bootstrap/00-bootstrap.sh
```
Creates state storage, lab RG, pipeline identity (OIDC), roles, SQL admin group, budget, GitHub variables + `lab` environment.

### C — Commit generated config + provider lock
```bash
cd infra
export ARM_SUBSCRIPTION_ID=$(az account show --query id -o tsv)
terraform init -backend-config=backend.hcl
terraform providers lock -platform=linux_amd64 -platform=darwin_arm64 -platform=windows_amd64
terraform plan          # optional local sanity check
cd ..
git add infra/backend.hcl infra/bootstrap.auto.tfvars infra/.terraform.lock.hcl
git commit -m "Bootstrap config + provider lock"
git push                 # first push → pipeline runs (Steps I → S)
```
Best practice from here: change via **pull request** → review plan → merge.

### I · D · A · W · S — Pipeline (push/merge to `main`, ~10–15 min first run)
```bash
git push origin main     # or merge a PR
```
| Job | Does | Depends on |
|---|---|---|
| plan | fmt, validate, plan (PRs stop here) | — |
| apply | applies the saved plan, exports outputs | plan |
| db | opens firewall for runner IP → schema → grant API MI → closes firewall | apply |
| api | `dotnet publish` → deploy via Entra (no publish profile) | db |
| web | build React with API URL → deploy to SWA (token fetched, masked, never stored) | api |
| smoke | `/api/hello` returns DB row; web returns 200 | web |

Open the URL printed in the **smoke** job.

### Teardown (three steps)
1. GitHub → Actions → **destroy** → run with `destroy`.
2. In the codespace: `bash bootstrap/99-teardown.sh` → type `teardown`.
3. github.com/codespaces → **Delete** the codespace (storage counts against the free quota while it exists).

Lab only (keep state, drop resources): step 1 only. Next push recreates everything.

## 6. Troubleshooting

| Symptom | Fix |
|---|---|
| Bootstrap: "gh is not authenticated with admin rights" | `unset GITHUB_TOKEN && gh auth login -s workflow`, re-run |
| `git push` refused: "workflow scope" | `gh auth login -s workflow && gh auth setup-git`, push again |
| Codespace build fails on a feature | Codespaces → ⋯ → **Rebuild container**; check the creation log |
| `az login` browser redirect fails in Codespaces | Use `az login --use-device-code` |
| `AADSTS700213/700016` at azure/login | Federated credential subject mismatch — check repo name/branch; re-run bootstrap |
| `AADSTS700024 assertion not within valid time` | Federated token expired (~5 min). Re-run job; login sits right before use |
| `403 AuthorizationPermissionMismatch` on state | RBAC propagation — wait 5 min, re-run |
| F1 plan creation fails (quota) | Only limited free Linux plans per region/subscription — delete old F1 plans |
| SQL free offer rejected | Free-offer DB limit reached for the subscription — delete an unused one, or set `useFreeLimit=false` (paid) |
| API returns 503 | Free DB resuming from pause (≤1 min) or free limit exhausted until 1st of month |
| `Login failed for user '<token-identified principal>'` | Re-run pipeline — `002` recreates the MI user (needed if the web app was recreated) |
| CORS error in browser | SWA hostname changed — re-apply so `api.tf` CORS updates |
| API slow first hit | F1 cold start (no Always On) — expected |

## 7. Risks (accepted for lab, fix before anything real)

| Risk | Lab stance | Production fix |
|---|---|---|
| SQL "Allow Azure services" | Accepted; Entra-only auth still required | VNet integration + private endpoint (needs B1+) |
| No environment approval gate | Free private repos lack required reviewers | Paid plan/public repo → required reviewers on `lab` |
| Actions pinned by tag | Acceptable | Pin to commit SHA + Dependabot |
| Contributor on RG | Least practical scope | Custom role with only used actions |
| Budget alerts don't stop spend | Free tiers + `AutoPause` make overrun unlikely | Action group → automation to stop resources |
| No SQL auditing / App Insights | Cost-driven omission | Enable both; Log Analytics with retention policy |
| Pipeline is SQL admin | Needed to grant MI | Separate migration identity; admin only via PIM |

**Rollback:** every change goes through PR → plan → apply. To roll back, revert the commit and re-run; state versioning (7 days) recovers a corrupted state file.

## 8. Glossary

| Term | Meaning |
|---|---|
| **AzAPI** | Terraform provider that calls Azure REST APIs directly — used for features azurerm lacks |
| **Codespaces** | GitHub-hosted cloud dev environment that runs the dev container in your browser |
| **CORS** | Cross-Origin Resource Sharing — browser rule allowing the SWA site to call the API |
| **Dev container** | A Docker container defined in `.devcontainer/` with every tool pre-installed |
| **Entra ID** | Microsoft Entra ID (formerly Azure AD) — identity platform |
| **F1** | Free App Service plan tier |
| **FIC** | Federated Identity Credential — trust between GitHub and an Entra app, replaces secrets |
| **LRS** | Locally Redundant Storage — cheapest replication |
| **MI** | Managed Identity — Azure-issued identity for a resource, no credentials to manage |
| **OIDC** | OpenID Connect — GitHub issues a short-lived token Azure trusts |
| **PIM** | Privileged Identity Management — just-in-time admin access |
| **PITR** | Point-In-Time Restore — SQL backup recovery |
| **RBAC** | Role-Based Access Control |
| **RG** | Resource Group |
| **SP** | Service Principal — the Entra identity the pipeline signs in as |
| **SWA** | Azure Static Web Apps |
| **TLS** | Transport Layer Security |
| **vCore** | Virtual CPU core — SQL free offer gives 100,000 vCore-seconds/month |
